# Panabit 系统升级包 DPI 特征库自动合并构建流

本项目基于 GitHub Actions 实现 Panabit 标准版（Linux/x86）系统升级包与最新 DPI 特征库（`dict.so` / `dpi.so`）的**自动同步、版本比对、文件属性保留合并及自动 Release 发布**。

## 🌟 核心特性

- **自动化同步监控**：每天自动检查 Panabit 官网的标准版系统安装包、升级包与 DPI 特征包（官网DIP特征包发布滞后，可通过官方QQ群下载最新包）。
- **差异增量备份**：官网一旦有更新，自动下载并提交归档至仓库的 `Panabit/` 与 `DPI/` `ISO/` 目录。
- **支持手动上传**：支持用户手动向 `DPI/` 或 `Panabit/` 目录上传特定版本的 `.pdb` / `.tar.gz` 文件,(可通过官方QQ群下载最新DIP包）。
- **智能去重与打补丁**：打包前自动比对最新文件组合（`系统升级包 + 特征包`）是否已发布，避免重复构建；合并时强制保留原始 `dict.so` 和 `dpi.so` 的修改时间戳（mtime）与文件权限。

🚀 使用指南
1. 全自动运行（推荐）
工作流会在每天 北京时间 18:00 (UTC 10:00) 自动触发运行：

自动比对官网最新版本。

若有更新，自动下载归档到仓库 Panabit/ 或 DPI/ ISO/ 目录。

自动生成包含最新 DPI 补丁的整合系统升级包并发布至 Releases。

2. 手动上传自定义特征包 / 主程序包
如果你获取到了内部或特定的 DPI 特征包（.pdb）或主程序包：

将你的 .pdb 文件直接上传提交到仓库的 DPI/ 文件夹（或将系统升级包上传至 Panabit/ 文件夹）。

在 GitHub 页面点击 Actions -> 选择 Panabit Repack with Latest DPI -> 点击 Run workflow 手动触发。

工作流会识别到 DPI/ 或 Panabit/ 目录下最新的文件组合，完成合并替换并发布新版本。

3. 手动触发即时检查
随时可以在 GitHub 仓库的 Actions 选项卡中，选择工作流并点击 Run workflow 手动触发一次检测与合并。

📝 替换说明
合并过程中会对文件执行以下操作：

解压 DPI 包并二次提取嵌套的 dict.so 及 dpi.so。

替换系统升级包内部 bin/dict.so 与 bin/dpi.so。

使用 cp -pf 强制保留原特征库文件的修改时间（mtime）与运行权限，确保 Panabit 系统识别正常。

⚠️ 注意事项
首次使用：请确保仓库中已创建 Panabit 和 DPI 文件夹（可以在文件夹内放一个 .gitkeep 文件以被 Git 追踪）。

权限要求：工作流配置了 permissions: contents: write，确保 Actions 有权限向仓库 Commit 备份文件以及创建 GitHub Release。
